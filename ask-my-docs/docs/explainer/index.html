A RAG project, explained in plain English

Ask My Docs

A small tool that answers questions from your own documents, and shows which passages each answer came from, so you can check it.

  • Runs on your own computer
  • No API key, no cost
  • Open source (MIT)
See the code on GitHub Watch the demos

The problem it solves

AI chat models are good at sounding sure. When they do not know something, they often make it up.

What RAG means

RAG stands for Retrieval-Augmented Generation. The name is long. The idea is short: let the AI look things up before it answers.

A normal AI: closed-book exam

It answers from memory. If the memory is wrong or missing, it can still give a confident answer.

A RAG system: open-book exam

It first finds the right pages in your notes, then writes the answer from those pages.

Retrieval

Find the passages in your documents that are most relevant to the question.

Augmented

Add those passages to the question, so the AI has the facts in front of it.

Generation

The AI writes the answer, using only those passages.

How Ask My Docs works

There are two parts. You prepare your documents once. After that, you can ask as many questions as you like.

Prepare once

Command: ingest

  1. Read the filesIt reads your .md, .txt and .pdf files. For PDFs it keeps the page number, so a citation can say which page it came from. You can point it at a folder, or add files from the web page.
  2. Cut them into passagesEach file is cut into short pieces of about 800 characters, at the end of a line or sentence, so each piece is about one thing.
  3. Turn passages into numbersA small AI model turns each passage into a long list of numbers that captures its meaning. This is called an embedding.
  4. Save the indexThe numbers are saved next to the text. This saved collection is the index.

Ask any time

Commands: ask or the web page

  1. You type a questionIn plain language, like talking to a person.
  2. The question becomes numbers tooThe same model does it, so questions and passages can be compared.
  3. Find the closest passagesThe tool compares the question with every passage and picks the 4 closest. This is the retrieval step.
  4. The AI writes the answerIt gets the 4 passages and the question. It is told to answer only from them, to cite them, and to say "I don't know" if the answer is not there.
  5. You see the answer and its sourcesCitations like [1] point to the passages, which are shown in full.

Why numbers? Passages with similar meaning get similar numbers, even when the words differ. "How many days can I work from home?" and "Employees may work remotely up to three days per week" share almost no words, but their numbers are close. That is how the right passage is found.

What was built

  • A command-line tool. ingest, ask, evaluate and serve.
  • A mobile-first web page. Swipeable passage cards, streaming answers, citations you can tap to read the full passage, and light and dark themes. You can add your own documents right from the page, and it works offline: even its fonts come from the app.
  • An evaluation command. It measures whether the right passage is found and whether the answers are right, using lists of test questions.
  • 150 automated tests. None of them needs the AI model, so they run anywhere.
  • Two sets of documents to try. A made-up company handbook (with a PDF in it), and notes about the author's portfolio.
  • Documentation. A README, a CLAUDE.md file for future work, the demo videos with the scripts that record them, and an MIT license.

Everything runs on one computer with Ollama. The answer model is Llama 3.2 (3 billion parameters, about 2 GB). The search model is nomic-embed-text (about 274 MB).

Does it work?

The project measures itself. These are the latest results from the evaluate command, with the small local model.

Read these with care. The questions were written by the author while building the tool, and the documents and prompt were changed after some failed. So the scores are on the optimistic side. They are best at catching things that break later.

One known weakness. Asked "Which courses did he complete in 2026?", the small model gets the list wrong every time. It leaves one out or adds a course from another year. The right passage is found. The model just writes the list badly. This case is kept in the tests on purpose, labelled as a known issue.

Problems found along the way, and the fixes

  • Answers that were only "[1]"The first prompt was too vague for a small model. Clear rules ("write full sentences, never reply with only a citation") raised an early 12-question check from 7 correct to 12.
  • Passages cut in the middle of a sentenceLong lists were chopped at fixed lengths. They are now cut at the end of a line or sentence, and each passage carries its document's title.
  • Contact details not foundThey were buried at the end of a long profile. A short, separate document that states each fact in a plain sentence fixed it.
  • Different answers on each runOne question passed once and failed 4 times out of 5. The AI's randomness is now turned off, so results repeat.
  • A wrong message found while recording the demoIn fast mode the evaluation said a known issue "now passes" when no answers had been checked. It now says so correctly, and a test covers it.

What it cannot do yet

  • The small model is slower and less careful than the big hosted ones. An answer takes about 5 to 15 seconds on an ordinary computer, and long lists can be wrong.
  • It reads .md, .txt and text-based .pdf files. Scanned PDFs (pictures of pages), Word files and web pages are not read.
  • The web page has no login, so it is meant for your own computer only. For that reason, adding documents from the page is switched off automatically if the server can be reached from other computers.
  • Adding a large PDF from the page can take a minute or more on an ordinary computer, because every passage is turned into numbers.
  • A bigger local model, or a hosted one, can be used by changing settings. No code changes are needed.

Words to know

RAG
Retrieval-Augmented Generation. Find the right passages first, then let the AI answer from them.
Passage
A short piece of a document, about one idea. Also called a chunk.
Embedding
A list of numbers that captures what a passage means. Similar meaning gives similar numbers.
Index
The saved passages and their numbers, ready to search.
Similarity
A score from 0 to 1 for how close a passage is to the question. Higher is closer.
Prompt
The full message sent to the AI: the rules, the passages, and the question.
Citation
A marker like [1] in the answer that points to the passage it came from.
Local model
An AI model that runs on your own computer instead of on a company's servers.
